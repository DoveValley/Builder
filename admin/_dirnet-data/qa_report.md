Dedupe key is **normalized street address + ZIP5**, never facility name: multi-site operators reuse
one name across dozens of locations, and collapsing on name would destroy the density being measured.
Normalization uppercases, strips punctuation, and folds the abbreviations the brief lists
(ST/STREET, AVE/AVENUE, RD/ROAD, STE/SUITE) plus DR/BLVD/HWY/PL/CT/LN/PKWY/TER/CIR and the four
compass directions.

**1329 rows have a blank `street1`** and were keyed on normalized name + ZIP instead of being
dropped. They are real licensed facilities with valid ZIPs — Central Peninsula General Hospital,
Fairbanks Native Association, Akeela Inc — and dropping them would understate density in exactly the
rural and tribal areas least able to absorb it. They still deduplicate across the two workbooks.

### Exclusions that are implicit, and the one I did not apply

The brief asks that four things be excluded from STRICT. Three need no veto, because none of them is
a STRICT code — a facility offering only that thing fails the any-of test already:

- **OTP-only** (methadone/buprenorphine dispensing): `OTP`, `MM`, `BUM`, `OMB` are not STRICT codes.
  Measured: 1563 facilities carry `OTP`, of which 893 also run residential, detox, PHP or IOP
  and so remain in STRICT on their own merits; the other 670 are excluded and counted in `otp_25`.
- **DUI/DWI-education-only**: `DUI`/`DUIO` are not STRICT codes. `DUIO` additionally vetoes.
- **Standard outpatient counselling with no SUD line**: `OP`/`ORT` are not STRICT codes.

**Halfway houses / sober living / transitional housing — I did NOT add a veto, against the brief's
literal wording, and this is the one filter decision worth challenging.** `HH` is not a STRICT code,
so a housing-only facility is already excluded. But a veto would also remove every facility that runs
transitional housing *alongside* clinical care, and that is almost all of them:

- 1,207 facilities carry `HH`
- **1,148 of those also carry a clinical STRICT code** (residential, detox, PHP or IOP)
- only 3 carry `RES` with no other STRICT code

So vetoing `HH` would delete ~1,148 real treatment facilities to exclude ~59 housing-only ones. I read
the brief's intent as "a sober home is not a rehab result", which the any-of test already delivers.
If you want the literal veto instead, add `HH` to `STRICT_VETO` and re-run — no refetch, ~10 seconds.

| code | codebook category · meaning |
| --- | --- |
| `OTP` | SU OT · Federally-certified Opioid Treatment Program |

`otp_25` counts OTP facilities within 25 miles **that are not already in STRICT**, so `strict_25` and
`otp_25` are disjoint and can be added without double-counting.

One judgement call to flag: `SOTP` ("SAMHSA certification for opioid treatment program", a
License/Certification code) is **not** unioned into the OTP bucket. The two disagree — 1,566 rows carry
`OTP`, 2,114 carry `SOTP`, 1,484 carry both. `OTP` is the Type-of-Opioid-Treatment code and is the
narrower, more literal reading of "opioid treatment program". Add `SOTP` to the `OTP` table to widen it.

## Distance and banding

Haversine great-circle distance, mean Earth radius 3958.7613 miles. No planar lat/long delta is used
anywhere. Band 1 is `d <= 25`, band 2 is `25 < d <= 60`, and a facility lands in exactly one — the
code is a single if/else-if per facility, so double-counting is structurally impossible. Nothing is
ever counted past 60 miles.

Because facilities are placed at ZIP centroids, a facility sitting within a mile or two of a band
boundary can fall on either side of it. That is inherent to ZIP-centroid resolution and is the
accuracy the brief specified as sufficient.

## Cities where `broad_25` exceeds `strict_25` by more than 4×

2 of 287 resolved cities. The brief flags this ratio as usually meaning the filter caught
something it should not have, so each of these is worth a look:

| city | state | strict_25 | broad_25 | ratio |
| --- | --- | --- | --- | --- |
| McAllen | TX | 1 | 5 | 5.0× |
| Eau Claire | WI | 4 | 19 | 4.8× |

Read these as a property of BROAD rather than of STRICT. BROAD is defined as every facility with any
treatment service, which in most markets is dominated by regular outpatient counselling — so a high
ratio marks a city whose supply is mostly outpatient, not necessarily a leaky filter. The cities to
actually distrust are ones with a high ratio **and** a low absolute `strict_25`, where a handful of
misclassified facilities would move the number a lot.

### Check 2 — passes, but the check cannot fully answer its own question

Both cities are above their tier median (Huntington 1.32×, Dayton 1.73×; MID tier, n=160, median 22),
and Dayton ranks 47/160 within its tier against Huntington's 61/160.

**The specific worry the check encodes — that the OTP exclusion is over-firing — is disproven.** The
exclusion only removes a facility from STRICT when it has *no* residential, detox, PHP or IOP service.
Its cost to these two cities is `otp_25`: **2 facilities for Huntington, 3 for Dayton**. Adding every
OTP back would move Huntington from 29 to 31 and Dayton from 38 to 41 — neither changes the picture, so
the exclusion is not what makes them look ordinary.

What this check *cannot* do is test "above what population suggests", because **the seed carries no
population column** and nothing in the SAMHSA files supplies one. `market_tier` is the only size
control available and it is coarse — MID spans a wide range. If you want this checked properly, add a
population column to the seed and the comparison becomes facilities-per-100k. I have not substituted
population figures from memory to make the check pass.

### Check 4 — fails as literally worded, and the check is the thing that is wrong

`sum(strict_25)` = **11704** against a national deduped STRICT total of **10667** — that is
**109.7%**, not a small fraction. Taken literally the check fails.

It fails because summing a per-city column is not a measure of anything: **the 287 radii overlap.**
Costa Mesa, Newport Beach, Santa Ana and Anaheim each count much of the same Orange County supply, so a
facility there is counted up to **6 times**, while a facility in rural Kansas is counted zero times.
The sum can legitimately exceed 100% while the distance filter works perfectly.

The concern behind the check — *is the distance filter actually being applied* — is answered by three
independent measures, and all three say yes:

| measure | value | what it would be with no distance filter |
| --- | --- | --- |
| distinct STRICT facilities within 25mi of ≥1 city | 7449 (69.8% of national) | 10,667 (100%) |
| distinct STRICT facilities within 60mi of ≥1 city | 9637 (90.3% of national) | 10,667 (100%) |
| STRICT facilities never within 25mi of any of the 287 | 3218 | 0 |
| max cities counting a single facility | 6 | 287 |
| sum if no filter were applied | — | 3,061,429 |

**3218 STRICT facilities are never counted by any of the 287 cities**, and the largest number of
cities sharing any one facility is 6. If the filter were absent the sum would be 3,061,429, not 11704.

That distinct coverage is 70% rather than something small is expected and not a defect: these 287
cities are the largest treatment markets in the country, and facilities cluster where people are. The
right restatement of this check is **"distinct coverage within 25mi should be well under 100% and a
large block of facilities should be unreachable"**, which is what the table above measures.

## Known limitations

- **N-SUMHSS is self-reported and annual.** These files carry the 2024 survey, published 2025, read
  2026-07-30. They lag closures and new openings by a year or more.
- **There is no carrier-level payment field.** Payment data is category-level only (private
  insurance, Medicaid, Medicare, military, cash, sliding scale). Nothing in this data indicates which
  facilities accept Cigna or Aetna specifically, and nothing here attempts to infer it.
- **The survey under-covers cash-pay and out-of-network facilities**, so density is understated in
  luxury markets. Treat these rows as floors, not estimates:

| city | state | strict_25 | broad_25 |
| --- | --- | --- | --- |
| Malibu | CA | 193 | 241 |
| Newport Beach | CA | 206 | 258 |
| Scottsdale | AZ | 142 | 224 |
| Delray Beach | FL | 98 | 138 |
| Boca Raton | FL | 92 | 138 |
| Bozeman | MT | 2 | 4 |
| Jackson | WY | 1 | 2 |

- **ZIP-centroid placement** puts every facility in a ZIP at one point. Fine for 25/60-mile band
  membership, as the brief says; it must never be used to state a distance to a named facility.
- **Radii overlap.** Neighbouring cities in one metro share facilities, by design — each row answers
  "what is near this city", so the column does not sum to a national total.
- **Both directories are counted as one universe.** A facility in both files is one facility with the
  union of its service codes, which is what lets a site reporting PHP in the mental-health file and
  detox in the substance-use file qualify on either.

## Reproducing / adjusting

```
npm run density                 # reuses cached geocoding, ~10s
npm run density -- --regeocode   # rebuild city coordinates from the Places gazetteer
```

Edit `STRICT`, `STRICT_VETO`, `BROAD` or `OTP` at the top of `scripts/density-counts.ts` and re-run.
Gazetteer downloads are cached on disk by `politeFetch` and city coordinates in
`data/density/city-geocodes.json`, so a filter change costs no network requests.

Source obligation: both gazetteer files come from `www2.census.gov`, registered in
`lib/sources/registry.ts` as `census-gazetteer` (public-domain federal reference data, 30s delay,
registered robots override). The register's `takes` line was widened for this job — it previously
named only the ZCTA file.
